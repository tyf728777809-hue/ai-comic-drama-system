# 失败类型指南

本文件定义 7 类失败的含义、识别方式和常见修复方向。

---

## 类型 1：业务审核失败

### 含义
业务审核 Agent 判定当前阶段产物质量不达标，给出 rejected 结论。

### 识别方式
- 审核结论文件中 verdict = fail
- reviewer = business-review-agent
- issues 列表中至少有 1 个 severity = critical 或 major

### 常见原因
- 关键字段缺失或过于模糊
- 叙事不连贯、节奏不合理
- 视觉描述不具体、无法执行
- 与上游 approved 内容不一致
- 可执行性不足（下游 Agent 无法基于此文件工作）

### 修复方向
1. 读取审核结论中的 issues 列表
2. 逐条处理 critical 和 major 级别问题
3. 补充缺失字段或优化不达标内容
4. 确保与上游已 approved 内容一致
5. 修改后重新提交审核

---

## 类型 2：合规审核失败

### 含义
合规审核 Agent 判定内容存在版权、人物权、敏感内容或平台限制风险。

### 识别方式
- 审核结论文件中 verdict = fail
- reviewer = compliance-review-agent
- risk_assessment 中至少有 1 项为 high

### 常见原因
- 涉及真实人物肖像或名字
- 涉及受版权保护的 IP 或角色
- 包含敏感政治/宗教/暴力内容
- 不符合目标平台的发布规则
- 未成年相关内容风险

### 修复方向
1. 读取审核结论中的 risk_assessment 和 issues
2. 确认高风险类型（copyright | portrait | content | platform）
3. 根据类型进行根本性修改
4. 如果涉及设定层面（如角色、世界观），需回退到创意定义阶段
5. 如果只涉及具体表达，在当前阶段修改即可
6. 修改后重新提交合规审核

### 优先级
合规失败优先级 **高于** 业务失败。合规失败必须立即阻断所有生成操作。

---

## 类型 3：内容缺失或文件结构不完整

### 含义
阶段产物文件存在但关键字段为空，或文件不存在但阶段标记为已开始。

### 识别方式
- 文件存在但必填字段为空字符串
- 文件存在但列表字段为空列表（如 characters: []）
- 文件不存在但项目状态显示该阶段进行中
- pending_items 中存在阻断型待确认项

### 常见原因
- 阶段产物未完成就提交审核
- Agent 中途中断
- 用户确认了不完整的设定
- 文件写入失败

### 修复方向
1. 列出所有缺失字段
2. 确认哪些缺失字段是阻断型的
3. 调用对应阶段的 Agent 补全
4. 补全后重新检查完整性
5. 确认无阻断项后再提交审核

---

## 类型 4：图像生成失败

### 含义
资产生产 Agent 调用图像生成工具后，结果不达标或生成失败。

### 识别方式
- 资产文件中 quality_check = fail
- 资产文件中 file_path 为空
- 资产文件中 status = rejected
- 生成工具返回错误

### 常见原因
- Prompt 描述不够具体或存在冲突
- 风格参考不明确
- 生成参数不合理
- 外部服务故障
- 图片与视觉描述不匹配

### 修复方向
1. 检查 prompt 是否准确反映视觉描述
2. 检查 negative_prompt 是否排除了问题元素
3. 优化 prompt 措辞和参数
4. 如果是服务故障，等待重试
5. 重新生成后进行质量检查
6. 通过后重新提交审核

---

## 类型 5：视频生成失败

### 含义
视频生产 Agent 调用视频生成工具后，结果不达标或生成失败。

### 识别方式
- 视频结果文件中 quality_check = fail
- 视频结果文件中 file_path 为空
- 视频结果文件中 status = rejected
- 生成工具返回错误

### 常见原因
- 视频 prompt 与首尾帧不一致
- 首尾帧之间差异过大
- 运动参数不合理
- 外部服务故障
- 视频与 segment 描述不匹配
- 衔接不连贯

### 修复方向
1. 检查首帧资产是否已 approved
2. 检查视频 prompt 是否准确反映 camera_movement 和 transition
3. 调整运动参数
4. 如果是首帧问题，先回退修复图片资产
5. 重新生成后进行质量检查
6. 通过后重新提交审核

---

## 类型 6：上下游依赖冲突

### 含义
下游阶段的产物引用了上游 rejected 或 draft 状态的产物。

### 识别方式
- 下游产物文件中 based_on 或 dependencies 引用了非 approved 的上游产物
- 上游产物状态变更后，下游产物未更新
- 不同 segment 的资产之间存在风格不一致

### 常见原因
- 上游修改后未通知下游
- 并行操作时使用了过期的上游版本
- 状态同步延迟

### 修复方向
1. 确认冲突的具体位置
2. 判断是上游需要修改还是下游需要重新生成
3. 如果是上游问题 → 回退到上游阶段修复
4. 如果是下游引用过期 → 使用最新 approved 版本重新生成下游
5. 消除冲突后重新提交审核

---

## 类型 7：版本冲突或状态冲突

### 含义
同一产物存在多个版本，或产物状态与实际内容不一致。

### 识别方式
- 同一产物存在多个版本文件（如 v1, v2）
- 多个版本中 status 不一致（如 v1 approved, v2 draft）
- 文件内容与 status 标注不匹配
- 不同文件引用了不同版本的上游产物

### 常见原因
- 并行修改未合并
- 回退后未清理过期版本
- Agent 使用了错误的版本号

### 修复方向
1. 确认哪个是最新有效版本
2. 确认哪个版本是下游正在引用的
3. 如果下游引用了错误版本 → 更新引用
4. 如果存在未合并的并行修改 → 合并后重新审核
5. 清理过期版本文件
6. 确认所有引用都指向正确版本
