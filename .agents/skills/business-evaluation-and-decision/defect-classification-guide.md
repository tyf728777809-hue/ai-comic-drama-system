# 缺陷分类指南

本文件定义业务审核中的缺陷分类标准，用于统一缺陷严重等级和归类方式。

---

## 缺陷严重等级

### 1. blocking（阻断型）

**定义**：该缺陷必须修复，否则产物不可放行。

**判定标准**（满足任一即为 blocking）：

| 条件 | 说明 |
|------|------|
| 内容缺失 | 关键字段为空或缺失（如角色无描述、segment 无 prompt） |
| 逻辑矛盾 | 产物内部存在自相矛盾（如角色 A 在前半段已死，后半段继续出场） |
| 连续性断裂 | 相邻段有明显不可接受的视觉或叙事断裂 |
| 无法执行 | 技术上不可实现（如超出 AI 工具能力范围） |
| 质量严重不达标 | 存在明显且影响使用的质量缺陷 |
| 结构缺失 | 核心结构不完整（如剧本无结尾、segment 总表缺少段落） |
| 合规前置阻断 | 合规审核标记为高风险的内容（业务审核需配合退回） |

**示例**：

| 阶段 | 缺陷描述 | 等级 |
|------|---------|------|
| 创意 | 核心创意无法用一句话概括，多人理解不一致 | blocking |
| 剧本 | 剧本缺少结尾，结构不完整 | blocking |
| 规划 | 某段落时长 30 秒，超出 15 秒分段上限且无拆分方案 | blocking |
| 资产 | SEG05 引用的角色资产完全缺失 | blocking |
| 视频 | 视频出现明显闪烁和变形，不可观看 | blocking |

---

### 2. major（重要缺陷）

**定义**：该缺陷强烈建议修复，但不一定阻断当前放行。如果 major 缺陷超过 2 个，应降级为 pass_with_revisions。

**判定标准**（满足任一即为 major）：

| 条件 | 说明 |
|------|------|
| 连续性风险 | 角色/场景有轻微不一致，尚可接受但有风险 |
| 叙事薄弱 | 叙事目标基本达成但不够有力 |
| 质量偏低 | 整体质量可接受但低于理想标准 |
| 资产不稳定 | 关键资产跨段有轻微风格偏移 |
| 衔接不够平滑 | 段间过渡有轻微跳跃但不影响理解 |
| 对白不够自然 | 对白功能正常但不够生动 |
| 节奏偏弱 | 节奏有变化但张力不足 |

**示例**：

| 阶段 | 缺陷描述 | 等级 |
|------|---------|------|
| 创意 | 人物关系成立但冲突不够尖锐 | major |
| 剧本 | 反转存在但铺垫不够，稍显突兀 | major |
| 规划 | 个别段落目的不够清晰但可推测 | major |
| 资产 | 同角色跨段颜色有轻微偏移 | major |
| 视频 | 段间过渡有轻微跳跃但不影响理解 | major |

---

### 3. minor（优化型）

**定义**：该缺陷不影响当前放行，可在后续迭代中优化。

**判定标准**（满足任一即为 minor）：

| 条件 | 说明 |
|------|------|
| 细节不完美 | 细节可优化但不影响整体质量 |
| 风格偏好 | 风格选择可优化但当前不违规 |
| 文案微调 | 文案可更精炼但当前表达准确 |
| 资产非关键 | 非关键资产有优化空间 |
| 衔接微调 | 衔接可更流畅但当前已达标 |

**示例**：

| 阶段 | 缺陷描述 | 等级 |
|------|---------|------|
| 创意 | 世界观细节可以更丰富 | minor |
| 剧本 | 某段对白可更精炼 | minor |
| 规划 | 某段过渡设计可更平滑 | minor |
| 资产 | 某背景资产细节可更丰富 | minor |
| 视频 | 某段情绪弧线可更突出 | minor |

## 缺陷归类字段

每条缺陷记录必须包含以下字段：

| 字段 | 说明 | 取值 |
|------|------|------|
| defect_id | 缺陷编号 | DEF-001, DEF-002, ... |
| dimension | 所属审核维度 | 引用 review-rubric.md 中的维度名 |
| severity | 严重等级 | blocking / major / minor |
| description | 问题描述 | 具体文字描述 |
| impact | 影响范围 | 受影响的 segment、角色、场景等 |
| suggested_fix | 建议修改方向 | 具体可执行的修改建议 |
| responsible_agent | 建议责任 Agent | 具体 Agent 名称 |
| requires_retrial | 修复后是否需要重审 | true / false |

## 缺陷严重等级与结论关系

| blocking 数量 | major 数量 | minor 数量 | 结论 |
|--------------|-----------|-----------|------|
| 0 | 0 | 0-3 | pass |
| 0 | 0 | 4+ | pass_with_revisions |
| 0 | 1-2 | 任意 | pass_with_revisions |
| 0 | 3+ | 任意 | fail |
| 1+ | 任意 | 任意 | fail |

---

## 使用规则

1. 每个审核维度发现的每个问题都必须归类
2. 不得遗漏任何 warning 或 fail 维度的问题
3. 严重等级判断以本文件标准为准，不得随意升降级
4. 缺陷描述必须具体，不得使用"不太对"、"需要优化"等模糊表述
5. suggested_fix 必须可执行，不得使用"看着改"等模糊建议
6. responsible_agent 必须是项目中定义的 Agent 名称之一
