# segment 规划与结构化拆解

## 适用场景

当已批准剧本需要拆解为 15 秒短段式生产结构时使用。适用于生产规划阶段的核心拆解工作。

不适用于创意生成、剧本写作、资产 prompt 生成、视频生成。

## 核心目标

1. 从 approved 剧本稳定拆出适合生产的 15 秒 segment
2. 保证每段既有独立任务价值，又能和上下段衔接
3. 让 segment 拆法天然适合后续资产和视频生产
4. 提前识别连续性和生产风险

## 输入

| 输入项 | 来源 | 必需 |
|--------|------|------|
| 正式剧本文件 | 剧本阶段产物 | 是 |
| 剧本阶段交接摘要 | script-finalization-and-handoff 输出 | 是 |
| 已锁定设定 | 创意设定文件 | 是 |
| 用户本轮反馈 | 用户指令 | 否 |
| 历史规划版本 | planning/ 目录 | 否 |

## 输出

| 输出项 | 格式 | 说明 |
|--------|------|------|
| segment 总表草稿 | YAML | 所有 segment 概览 |
| 单段任务文件草稿 | YAML × N | 每个 segment 详细任务 |
| 连续性风险提示 | 列表 | 引用 continuity-risk-checklist |
| 生产风险提示 | 列表 | 按类别标注 |
| 替代拆法建议 | 列表 | 针对问题段落的备选方案 |
| 待确认项 | 列表 | 需要用户决定的内容 |

## 执行步骤

### 步骤 1：读取剧本与交接摘要

1. 读取正式剧本文件，确认 status = approved
2. 读取剧本阶段交接摘要，了解：
   - 剧本结构（幕/场景/节拍）
   - 关键角色和关系
   - 核心冲突和情绪弧线
   - 已标注的生产注意事项
3. 读取已锁定设定，确认世界观、角色外观、场景风格等不可变要素
4. 如果 status 不是 approved，拒绝执行并报错

### 步骤 2：检查输入是否足够做生产规划

1. 确认剧本完整性：是否有明确的幕结构、场景划分、对白/动作描述
2. 确认设定完整性：角色外观、场景描述是否足够提取资产需求
3. 如果缺失关键信息：
   - 列出缺失项
   - 标记为阻断项
   - 不强行拆段，等待补全

### 步骤 3：按剧情推进进行 segment 拆解

1. 按 [segment-planning-rules.md](segment-planning-rules.md) 的规则进行拆解
2. 优先按剧情节拍拆分，其次考虑时间和生产可行性
3. 每个候选 segment 必须通过以下检查：
   - 是否有明确的剧情目的（钩子/推进/转折/收尾）
   - 是否有明确的动作或情绪变化
   - 是否适合 10-15 秒的视频时长
   - 是否能明确提取角色和场景需求
4. 不通过检查的候选段需要调整拆法或合并

### 步骤 4：为每个 segment 编号

1. 按 [segment-id-rules.md](segment-id-rules.md) 的规则为每个 segment 分配唯一编号
2. 编号必须稳定：同一段落在不同版本中保持相同编号（除非拆法改变）
3. 编号必须连续：SEG01、SEG02、SEG03...

### 步骤 5：为每个 segment 补齐任务信息

1. 按 [segment-structuring-template.md](segment-structuring-template.md) 为每个 segment 填写：
   - 剧情目的
   - 详细内容摘要
   - 关键角色与状态
   - 关键动作与情绪
   - 场景信息
   - 上下段衔接说明
   - 首尾帧建议
   - 资产提示
2. 信息来源严格基于已批准剧本，不得自行创作新内容
3. 无法确认的项标记为"待确认"

### 步骤 6：做连续性检查

1. 按 [continuity-risk-checklist.md](continuity-risk-checklist.md) 逐项检查
2. 重点检查：
   - 相邻段动作是否衔接
   - 情绪状态是否连贯
   - 场景切换是否合理
   - 首尾帧是否兼容
   - 角色外观/服装是否一致
3. 标记所有风险点和严重等级

### 步骤 7：做生产风险检查

1. 检查每个 segment 的生产可行性：
   - 是否有过复杂的动作/调度
   - 是否有过多角色同框（群像 >3 人）
   - 是否有难以 AI 生成的场景
   - 是否有高成本资产生成需求
2. 对高风险段落给出风险说明和缓解建议

### 步骤 8：必要时给出替代拆法

1. 对存在风险的段落，给出 2-3 种替代拆法：
   - 每种拆法的优点和风险
   - 对相邻段的影响
   - 对下游资产/视频阶段的影响
2. 推荐最优拆法并说明理由

### 步骤 9：输出当前版本结果

1. 输出 segment 总表草稿和单段任务文件草稿
2. 输出所有风险提示和待确认项
3. 将结果传递给 `segment-finalization-and-handoff` skill 做定稿整理

## 约束边界

| 约束 | 说明 |
|------|------|
| 不改剧本 | 严格遵守 approved 剧本，不得自行修改 |
| 不写分镜 | 只做 segment 级拆解，不做镜头级设计 |
| 不写资产 prompt | 只提示资产需求，不写具体生图 prompt |
| 不调用工具 | 不调用 Dream Maker 或任何执行型工具 |
| 不脑补 | 信息不足时标记"待确认"，不自行编造 |

## 完成标准

执行完成后，必须能明确回答以下 5 个问题：

1. 当前拆段版本是什么？ → 已输出版本号
2. 是否已形成完整 segment 结构？ → 总表 + 单段文件已完成
3. 是否还有明显连续性风险？ → 已列出并分级
4. 是否还有明显生产风险？ → 已列出并分级
5. 下一步是继续修正还是进入定稿？ → 已给出建议
