# 创意设定定稿与剧本交接

## 适用场景

当 `creative-discovery-and-convergence` skill 完成创意收敛、用户基本确认创意方向后，本 skill 负责将结果整理为正式文件并交接给剧本开发阶段。

不适用于创意访谈和收敛（由 creative-discovery-and-convergence 负责）、剧本写作、资产规划。

## 核心目标

1. 把已成熟的创意结果整理为正式文件
2. 给用户一个适合确认的复盘摘要
3. 把创意阶段结果稳定交给剧本阶段
4. 管理版本号和确认状态
5. 明确哪些内容已经锁定、哪些仍可细化

## 输入

| 输入项 | 来源 | 必需 |
|--------|------|------|
| 当前最新创意收敛结果 | creative-discovery-and-convergence 输出 | 是 |
| 创意风险提示 | creative-discovery-and-convergence 输出 | 是 |
| 用户反馈 | 用户确认/修改意见 | 否 |
| 当前版本号 | 历史版本文件 | 是 |
| 当前状态 | 历史版本文件 | 是 |

## 输出

| 输出项 | 文件 | 说明 |
|--------|------|------|
| 正式创意设定文件 | `project_data/series/creative-bible-v{version}.yaml` | 完整创意 Bible |
| 确认前复盘摘要 | `project_data/series/review-summary-v{version}.yaml` | 面向用户的确认清单 |
| 剧本阶段交接摘要 | `project_data/series/script-handoff-v{version}.yaml` | 面向剧本开发 Agent 的交接 |

## 执行步骤

### 步骤 1：读取当前最新创意版本

1. 读取 `creative-discovery-and-convergence` 输出的收敛摘要
2. 读取最新的创意风险检查结果
3. 读取历史版本文件（如果有），确认当前版本号
4. 确认当前状态：是否有未解决的待确认项

### 步骤 2：判断是否具备定稿条件

1. 检查 P0 字段是否全部已明确（题材、风格、premise、主角）
2. 检查 P1 字段缺失数量（建议 ≤ 2）
3. 检查是否还有高风险创意风险未解决
4. 判定结果：
   - **可定稿**：P0 全满，P1 缺失 ≤ 2，无高风险 → 进入步骤 3
   - **附条件定稿**：P0 全满，有中风险 → 标记风险后进入步骤 3
   - **不可定稿**：P0 有缺失或存在未解决高风险 → 建议回到 creative-discovery-and-convergence 继续访谈

### 步骤 3：整理正式创意设定文件

1. 按 [creative-bible-template.md](creative-bible-template.md) 填写正式创意设定文件
2. 确保以下部分完整：
   - metadata：项目名称、版本号、状态
   - 作品定位：题材、风格、受众、钩子
   - 故事核心：premise、核心冲突、核心卖点
   - 角色设定：主角、主要配角、人物关系
   - 世界观：设定规则、视觉风格
   - 生产参数：单集时长、集数、作品形态
   - 边界条件：禁区、商业目标、风险提示
   - 待确认项：所有未明确内容
3. 版本号按 [version-status-rules.md](version-status-rules.md) 规则递增

### 步骤 4：生成确认前复盘摘要

1. 按 [review-summary-template.md](review-summary-template.md) 生成给用户的复盘摘要
2. 复盘摘要必须能让用户快速判断"要不要确认"：
   - 已确认的内容（简明列出）
   - 待确认的内容（明确标出）
   - 已识别的风险（按高/中/低）
   - 确认后的下一步（进入审核 → 进入剧本阶段）
   - 不确认的选项（继续修改 → 重新收敛）
3. 复盘摘要语言要面向用户，不要用内部术语

### 步骤 5：生成剧本阶段交接摘要

1. 按 [script-handoff-template.md](script-handoff-template.md) 生成给剧本开发 Agent 的交接摘要
2. 交接摘要必须能让剧本 Agent 立刻开始工作：
   - 项目讲什么（premise + 核心冲突）
   - 核心角色是谁（主角 + 主要配角，含关键设定）
   - 核心关系是什么（人物关系和张力来源）
   - 风格基调是什么（情绪基调 + 叙事节奏）
   - 哪些设定不能改（已锁定的核心设定）
   - 哪些地方仍可探索（待确认项和可细化空间）
   - 当前版本号和引用文件路径
3. 明确标注"已锁定"和"可探索"的边界

### 步骤 6：更新版本号与状态字段

1. 根据 [version-status-rules.md](version-status-rules.md) 更新版本号和状态：
   - 初始定稿 → draft
   - 提交用户确认 → in_review
   - 用户确认 → approved
   - 用户退回修改 → rejected → 修改后重新 draft
2. 写入 changelog 记录本次变更
3. 更新所有输出文件的 metadata

## 约束边界

| 约束 | 说明 |
|------|------|
| 不继续创意发散 | 定稿阶段只整理，不发散新方向 |
| 不越权做剧本工作 | 不写剧本、不拆段、不设计分镜 |
| 不调用 Dream Maker | 不涉及任何执行型生产工具 |
| 不代替用户确认 | 只提供复盘摘要，由用户决定确认或退回 |
| 不修改审核对象 | 创意设定文件在用户确认前状态为 draft |

## 完成标准

执行完成后，必须能明确回答以下 4 个问题：

1. 当前创意是否已经达到定稿条件？ → 已判定可定稿/附条件定稿/不可定稿
2. 当前正式版本号是什么？ → 已生成带版本号的正式文件
3. 当前确认状态是什么？ → 已设置 draft/in_review 状态
4. 是否已经具备交给剧本阶段的条件？ → 已生成交接摘要，等待用户确认后可交接
